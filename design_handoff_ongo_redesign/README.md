# Handoff: onGo — 크리에이터 영상 자동업로드 SaaS UI/UX 리디자인

## Overview
onGo는 1인 크리에이터가 매일 영상을 여러 플랫폼(YouTube, Instagram, TikTok, Threads, Facebook, Naver 블로그)에 자동 업로드하고, 댓글·DM을 응답하고, 성과를 확인하는 통합 도구입니다.

이 리디자인의 목표는 세 가지입니다.

1. **기능별 메뉴 → 하루 작업 순서로 재편.** `오늘 → 만들기 → 응답 → 확인` 축으로 내비게이션을 재배열. 설정성 화면은 하단으로 분리.
2. **고밀도·키보드 우선.** 매일 쓰는 파워유저 기준. 목록은 카드가 아닌 테이블 행, 행 높이 44~48px, `/` 검색 · `⌘↵` 예약/전송.
3. **실패를 숨기지 않기.** 자동화 SaaS의 신뢰는 실패 알림에서 나옵니다. 토큰 만료·플랫폼 한도·발행 실패를 대시보드 최상단에 상시 노출.

로그인 화면은 기존 디자인을 유지합니다(사용자 요청). 리디자인은 로그인 이후 전 영역입니다.

## About the Design Files
이 번들에 포함된 `onGo Redesign.dc.html` 은 **HTML로 만든 디자인 레퍼런스**입니다. 의도한 레이아웃·색·타이포·상호작용을 보여주는 프로토타입이며, 그대로 복사해 배포할 프로덕션 코드가 아닙니다.

작업 내용은 **이 HTML 디자인을 대상 코드베이스의 기존 환경(React/Vue/Next 등)과 기존 컴포넌트·패턴·상태관리 방식으로 재현하는 것**입니다. 아직 프론트엔드 환경이 정해지지 않았다면 프로젝트에 가장 적합한 프레임워크를 선택해 구현하십시오. 파일 내부의 `<x-dc>`, `<sc-for>`, `<sc-if>`, `renderVals()` 같은 태그/구조는 프로토타입 전용 런타임이므로 이식 대상이 아닙니다 — 각각 `map()`, 조건 렌더링, 컴포넌트 상태로 옮기면 됩니다.

## Fidelity
**High-fidelity (hifi).** 색상 hex, 폰트, 간격, 라운드, 상태 배지 색까지 확정된 시안입니다. 픽셀 단위로 재현하되, 대상 코드베이스에 이미 있는 버튼/입력/토글 프리미티브가 있다면 그것을 사용하고 스타일 값만 맞추십시오. 데이터는 모두 목업이며 실제 API로 대체해야 합니다.

  - 좌: 성과 상위 영상 테이블. 컬럼 grid `34px minmax(0,1fr) 76px 62px 76px 62px`, 헤더는 모노 10.5px 대문자(`# / TITLE / VIEWS / WATCH / FOLLOW / TREND`), 숫자는 모노 우측 정렬. 5행(최상위 = 아침 5분 루틴 812K / 74% / +2,140 / 상승)

## Interactions & Behavior
- **내비게이션**: 레일 항목 클릭으로 화면 전환. 프로토타입은 단일 상태(`screen`)이며, 실제로는 라우트로: `/today`, `/compose`, `/inbox`, `/calendar`, `/performance`, `/channels`, `/settings`
- **딥링크 진입**: 확인 필요 CTA, 큐 행의 상태 배지, 캘린더 빈 슬롯은 모두 대상 화면으로 컨텍스트를 가지고 진입(예: 썸네일 지정 → 해당 초안 컴포저의 썸네일 필드 포커스)
- **키보드**: `/` 검색 포커스, `⌘↵` 예약/전송, `J`/`K` 목록 위아래, `E` 완료, `⌘K` 커맨드 팔레트(권장 확장)
- **hover**: 테이블 행 배경 `#1f2233`; 보조 버튼 보더 `#262940 → #3a3f61` + 글자 `#fff`; accent 버튼 `filter: brightness(1.1)`; 점선 CTA 보더/글자 accent. 트랜지션 120ms `ease-out` 권장(프로토타입은 미지정)
- **로딩**: 큐/목록은 행 높이를 유지한 스켈레톤. 컴포저 업로드는 파일 카드 안 진행률(자막 진행 62% 처럼 텍스트 병기)
- **에러**: 발행 실패는 (1) 오늘 화면 `확인 필요`, (2) 채널 화면 상단 배너, (3) 해당 큐 행 배지 — 세 곳에 동시 반영. 자동 재시도 3회 후에도 실패면 푸시/이메일
- **검증**: 제목 길이(플랫폼별 상한), 해시태그 개수(TikTok 5), 롱폼 썸네일 필수, 만료 채널이 대상에 포함되면 예약 버튼 비활성 + 사유 표시
- **반응형**: ≥1440 3열 유지 / 1024~1440 인박스 필터 열 접기(아이콘), 컴포저 우측 패널 320px / <1024 단일 열 + 하단 탭(모바일 규칙 적용)

## State Management
프로토타입 상태(그대로 참고 가능):
- `screen` — 활성 화면
- `tab` — 컴포저 플랫폼 탭 (`common | YT | IG | TT | NV`)
- `preview` — 프리뷰 플랫폼
- `sched` — 예약 방식 (`now | best | fix`)
- `off` — 플랫폼별 대상 해제 맵 `{YT: true, …}`
- `filter` — 인박스 필터
- `thread` — 선택된 스레드 인덱스
- `range` — 성과 기간 (`7d | 30d | 90d`)
- `setTab` — 설정 서브 탭

필요한 데이터 페치: 오늘 큐(예약 목록+상태), 알림/헬스 체크, 채널 연결 상태와 한도, 스레드 목록(페이지네이션·필터), 스레드 상세+대상 게시물 지표, 성과 시계열+상위 영상, 주간 예약, 설정. 발행 상태와 인박스는 폴링 또는 소켓으로 갱신(실패 알림이 즉시 보여야 함).
